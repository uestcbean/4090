# 面向 MLE 转型的项目证据

本项目重点证明模型部署、评估、性能分析和服务工程能力。它主要覆盖 MLE 中的推理系统方向，不等同于完整的数据/训练/业务迭代经历。

## 需要能够现场展示的能力

| 能力 | 证据 | 对应步骤 |
|---|---|---|
| 理解模型推理 | KV 显存推导、prefill/decode 分析 | 01、02、06 |
| 模型评估 | BF16 参考、量化质量门槛与退化案例 | 03、10 |
| 系统测量 | 可复现压测、分位数、goodput、容量曲线 | 04、05、07 |
| 性能工程 | 调度/缓存/量化实验与消融 | 06–11、14 |
| 独立底层实现 | 正确性测试、Triton 代码、代表性 benchmark | 12 |
| 服务工程 | 鉴权、背压、取消、恢复与稳定性记录 | 13 |
| 工程沟通 | 可追溯 Git 历史、复现文档、失败分析 | 全程 |

## 简历描述模板：实测后才能填写

项目名：RTX 4090 单卡 LLM 推理服务与性能优化。

- 构建基于 [实际模型/引擎版本] 的流式推理服务，完成 [实际实现的鉴权/队列/取消/恢复]，并通过 Prometheus/Grafana 监控延迟、吞吐、KV 与 GPU 指标。
- 在 RTX 4090 24GB、[输入输出分布]、[SLO] 与 [质量门槛] 下，通过 [实际验证有效的优化] 将 goodput 从 [A] 提升至 [B] req/s（[百分比]），并报告 [重复次数与波动]。
- 基于 profiling 实现 [具体 Triton 算子]，在 [shape/dtype] 下较 [明确基线] 加速 [X]；[若真实测得，填写端到端收益；未接入则注明独立算子实验]。

不必强行凑满三条。最终选择证据最强、与目标岗位最相关的两到三条。

## 贡献边界

- 使用 vLLM 内建机制：写“部署/调优/评估”，不写“自主实现 PagedAttention”。
- 自己写的代码：可以写“实现”，注明依赖和复用的课程代码。
- 算子加速与服务加速分开；局部提升不得包装成端到端提升。
- 压测客户端数不等于真实用户数；模拟负载不称真实线上流量。
- 仅本地或私网部署不写“已上线生产”；一小时稳定测试不写高可用 SLA。
- 无收益实验保留，它能证明你了解方法的适用条件。

## 最终展示顺序

用 3–5 分钟讲清：场景与约束 → 基准 → 瓶颈证据 → 有效/无效实验 → 最终取舍 → 复现方式。
准备一张架构图、一张吞吐—延迟曲线、一张质量/显存权衡表、一段真实服务演示。
GitHub README 直接链接最终报告、配置、关键代码和结果提交，方便面试官快速核查。
